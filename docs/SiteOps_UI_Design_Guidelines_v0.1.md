# SiteOps UIデザインガイドライン v0.1

- ステータス：確定
- 対象：SiteOps v0.1 の認証画面、オンボーディング、管理画面
- 技術基盤：Next.js 16 / React 19 / TypeScript / Tailwind CSS 4 / shadcn/ui

## 1. デザインコンセプト

**モダン・プロフェッショナル × シンプル・ミニマル**。

> Webサイト運用を、シンプルに。

Web制作会社・フリーランスが、顧客・Webサイト・ドメイン・SSL・保守契約・タスク・作業履歴を迷わず管理できるUIを目指す。信頼感、清潔感、視認性、操作性を優先し、不要な装飾を避ける。情報の重要度、期限、次に取るべき操作が分かることを重視する。

## 5. UIコンポーネント

**フラット・ミニマル**。shadcn/uiを基本とし、Tailwind CSSで拡張する。原則として影よりボーダーで領域を分ける。

| コンポーネント             | 仕様                                     |
| -------------------------- | ---------------------------------------- |
| ボタン                     | 高さ36px、角丸8px、文字14px/500          |
| 入力欄                     | 高さ40px、角丸8px                        |
| カード                     | 白背景、角丸12px、1pxのBorder            |
| テーブル                   | 行高48〜52px、文字14px                   |
| テーブルヘッダー・行ホバー | `#F8FAFC`                                |
| モーダル                   | 角丸12px、最大幅480〜560px               |
| バッジ                     | 角丸6px、ステータス別配色                |
| ドロップダウン             | 白背景、角丸8px                          |
| Toast                      | 原則画面右下。モバイルでは表示領域を考慮 |

ボタンの種類：Primary（保存・登録）、Secondary（戻る・キャンセル）、Destructive（削除）。同一操作領域のPrimaryは原則1つ。削除などの不可逆操作は確認を設ける。フォームには明確なラベル、入力エラー、送信中・成功・失敗状態を用意する。

一覧は検索・フィルター・並べ替え・ページングの必要性を画面ごとに判断する。空状態では理由と次のアクションを示す。読み込み中、エラー、権限不足も明示する。

## 6. レスポンシブ設計

**PC優先＋モバイル完全対応**。画面幅によって切り替え、端末種別には依存しない。

| 画面幅                      | レイアウト                 | 余白 |
| --------------------------- | -------------------------- | ---: |
| 1024px以上（PC）            | サイドバー通常／折りたたみ | 32px |
| 640〜1023px（タブレット）   | ドロワー式ナビゲーション   | 24px |
| 639px以下（スマートフォン） | ドロワー式ナビゲーション   | 16px |

スマホではKPIカードを1列、フォームを原則1列にする。テーブルはデータの性質に応じて横スクロールかカード表示を選ぶ。スマホでも主要な閲覧・登録・編集・期限確認を可能にする。タッチ操作に使うボタンは原則40〜44px以上の操作領域を確保する。横スクロールが必要な場合は分かりやすく示す。

## 7. 共通デザインルール

### 7.1 余白

8pxを基本単位とする。代表値：8 / 16 / 24 / 32 / 48px。

| 用途           |     目安 |
| -------------- | -------: |
| アイコンと文字 |      8px |
| フォーム項目間 |     16px |
| カード内部     |     24px |
| カード間       | 16〜24px |
| セクション間   |     32px |
| 大きな区切り   |     48px |

### 7.2 角丸

ボタン・入力・ドロップダウン8px、カード・モーダル12px、バッジ6px。

### 7.3 アイコン

Lucide Iconsを使用する。サイドバー18〜20px、ボタン内16px、ステータス16px、案内表示24〜32px。アイコン単独の操作には`aria-label`やTooltipを付ける。

### 7.4 アニメーション

ボタンホバー150ms、サイドバー開閉200ms、モーダル150〜200ms、ドロップダウン150ms。ページ遷移の装飾的アニメーションは原則なし。`prefers-reduced-motion`を尊重する。

### 7.5 テーマ

v0.1はライトモードのみ。将来のダークモード追加を考慮して、色の直接指定をコンポーネントに散在させず、CSS変数・セマンティックトークンで管理する。

### 7.6 アクセシビリティ

キーボード操作、視認できるフォーカス、フォームラベル、エラー説明、適切なコントラスト、ステータスの非色依存表示、タップ領域を重視する。目安として通常テキストはWCAG AAの4.5:1以上、大きな文字は3:1以上を確認する。モーダルではフォーカス移動と復帰を適切に扱う。

## 8. 実装運用ルール

1. 新規画面は本書と`AGENTS.md`、`docs/SiteOps_v0.1_requirements.md`を参照する。
2. shadcn/ui既存コンポーネントを優先し、重複した独自UIを増やさない。
3. カラー・余白・角丸はトークンを優先し、マジックナンバーを減らす。
4. 認証画面、オンボーディング、管理画面で視覚言語を統一する。ただし認証画面はサイドバー不要。
5. レスポンシブ・キーボード操作・空状態・エラー状態を実装時の確認項目とする。
6. 既存の認証・セキュリティ・RLS・業務ロジックを、デザイン変更のために不用意に変更しない。
7. 本書にない仕様は既存デザインとの一貫性を優先し、重要な新ルールは合意後に本書へ追記する。

## 9. 確定履歴

STEP 1〜7を対話で決定。今後の実装で使用する正式なUIデザイン基準とする。
